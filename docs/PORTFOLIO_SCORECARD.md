# Portfolio Scorecard

A project can move from `learning` to `portfolio` when most of the following are true.

- [ ] README explains the problem and why it exists.
- [ ] Architecture diagram or precise textual architecture exists.
- [ ] Clean build works from a fresh checkout.
- [ ] Tests cover success, failure and edge cases.
- [ ] At least one regression test corresponds to a real bug encountered during development.
- [ ] Benchmark methodology is written before performance claims.
- [ ] Raw small benchmark output is preserved.
- [ ] Profiling evidence supports optimization work.
- [ ] Sanitizer/fuzz/property testing is used where appropriate.
- [ ] Limitations and unsupported cases are explicit.
- [ ] Design trade-offs are recorded in ADRs.
- [ ] At least one research question or comparative experiment exists.
- [ ] CI runs on relevant supported platforms.
- [ ] Commit history shows incremental development.
- [ ] A tagged release exists when a meaningful milestone is reached.
- [ ] External issue/patch/user feedback exists for mature projects.
