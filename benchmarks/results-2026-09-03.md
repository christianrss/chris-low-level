# Day 01 portable benchmark baseline

These values were collected while validating the generated repository. They are **not** performance claims about the user's machine and should be re-run locally before publishing comparisons.

## Validation environment

- OS/kernel: Linux 6.18.35 x86_64
- C/C++ compiler: GCC 14.2.0
- Python: 3.13.5
- CMake: 3.31.6
- Build type: Release for native targets

## Results

| Project | Workload | Result | Important limitation |
|---|---|---:|---|
| chris-vm | 30 executions of a 19-byte arithmetic program | median 1.1774 ms | process startup and stdout included |
| chris-autograd | Python linear training, 1000 epochs, 50 runs | median 0.5086 ms | scalar toy workload; no C in-process comparison yet |
| chris-disassembler | inspect 15,960-byte benign executable, 30 runs | median 1.2773 ms | process startup + textual rendering included |
| chris-binary-toolkit | scan 1 MiB | 16.31 MiB/s | pure Python implementation |
| chris-binary-toolkit | scan 4 MiB | 16.24 MiB/s | pure Python implementation |
| chris-binary-toolkit | scan 8 MiB | 16.28 MiB/s | pure Python implementation |
| chris-renderer | 1,000,000 physics + draw-list core iterations | 162.938 ns/iteration | no rasterization/window/GPU work included |

## Interpretation

The first three process-based benchmarks are deliberately coarse baselines. Their main value is to expose methodology problems that should be fixed in later experiments. The binary scanner scales approximately linearly across the tested sizes in this environment. The renderer measurement isolates only the portable scene core and should not be presented as a renderer frame-time benchmark.

## Reproduce

```bash
python scripts/run_all_benchmarks.py
```

Record a new local result with your CPU, OS, compiler flags and date before making before/after optimization claims.
