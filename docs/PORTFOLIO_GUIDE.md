# Portfolio guide

The strongest evidence in this repository should be the software and experiments themselves.

For each mature project, keep:

- an architecture diagram;
- a concise problem statement;
- documented design decisions and trade-offs;
- tests and CI;
- benchmark methodology and results;
- profiler evidence for optimization work;
- limitations and future work;
- references to specifications or papers;
- a small demo or reproducible command.

When a project becomes substantial, it can be split into a dedicated public repository while this monorepo remains the learning history.
